STARTcraft v66 - 대체 공중 확장 / 두 게임 창 모드 통일

1. 게임과 봇을 모두 종료하고 새 폴더에 압축을 해제합니다.
2. upgrade_ai_v66.cmd를 실행합니다. 검증된 v54-v65 소스를 지원합니다.
3. 반드시 이번 ZIP의 run_STARTcraft_vs_Pluto.cmd로 경기를 시작합니다.
   이전 폴더의 런처는 새 창 모드 설정을 적용하지 않습니다.
   기본값: 두 게임 모두 창 모드, 640x480, 좌우 배치.
   런처는 두 bwapi.ini를 백업한 후 변경하고 프로세스별 환경 변수도 지정합니다.
   전체화면을 원하면 명령 프롬프트에서 다음을 실행합니다:
   run_STARTcraft_vs_Pluto.cmd -WindowMode Fullscreen

앞마당 준비가 지속적으로 안 되는 경우, SCV 18/팩토리 1/탱크 2 조건에서
720프레임 대기 후 대체 확장을 계획합니다. 본진 커맨드는 띄우지 않습니다.
새 커맨드를 본진의 건설 가능한 자리에 지어 광물 멀티로 날립니다.
가스가 없거나 광물벽 때문에 지상 접근이 안 되는 후보도 검색합니다.
착륙 뒤 현지 SCV를 생산하며 현지 광물을 채굴/운반하는 일꾼 4명을 확인해야 AIR_ACTIVE를 기록합니다.
안전하지 않거나 명령/이동이 정체되면 다른 후보를 찾거나 본진으로 돌아옵니다.
후보가 없을 때 적진이나 불법 위치에 강제 착륙하지 않습니다.
공중 확장 자금은 생산 예산에 반영합니다. 앞마당 군대 진출 로직은 유지합니다.

사용자가 보낸 v65: 앞마당 완료와 두 번째 커맨드 건설이 없었습니다.
이전의 탱크 이동 정체는 회복했지만 경제 확장이 뒤따르지 않은 상황입니다.

검증: 현재 소스 기준 두 시드 각각 생산/경로/이동/비행 의사결정 1,000건.
비행 검사는 실제 C++ 결정 함수를 실행하며, 매 시나리오 14개 조건을 확인합니다.
전체 확장 관리자도 모의 명령/자원 환경에서 1,000건 실행했습니다.
600건 활성화, 100건 커맨드 손실 감지, 300건 안전 대기/정체로 구분했습니다.
이 검사는 지형 후보 검색, 실제 명령 수락/건설/비행/채굴을 재현하지 않습니다.
모델 결과는 실전 승률이 아닙니다. Windows 전체 빌드/화면/실전은 미검증입니다.
공식 BWAPI 4.4 헤더 문법, PowerShell 구문, INI 백업/설정, 설치/복원 모의 검사를 수행합니다.
CSV 파일명은 기존과 같고 construction의 version은 66입니다.
다음 경기 construction CSV에서 AIR_PLAN/BUILD_HOME/LIFT/LAND/SEED/ACTIVE와
AIR_REPLAN/CC_LOST/NO_SITE를 리플레이와 함께 확인해야 합니다.
